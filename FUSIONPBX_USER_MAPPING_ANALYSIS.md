# FusionPBX User Mapping Analysis

## Date: 2025-11-18

## Issue Summary

**User cannot find `giraud.eric@gmail.com` in FusionPBX GUI**

## Root Cause Analysis

### 1. Database Status

```sql
-- PostgreSQL (ai.epic.dm) user record:
SELECT id, email, fusionpbx_api_key, fusionpbx_user_uuid FROM users WHERE email = 'giraud.eric@gmail.com';

Result:
- id: 0efe6c17-7b1f-4d78-a0c8-bb53acb60e71
- email: giraud.eric@gmail.com
- fusionpbx_api_key: ak_d9b73cd80a8082ca8cb8e1bc125d8603
- fusionpbx_user_uuid: NULL ❌
```

```sql
-- Agent configs (3 sample agents):
SELECT id, name, sip_username, did_number, fusionpbx_agent_uuid FROM agent_configs;

Results:
1. Customer Support Agent:  sip_username=NULL, did_number=NULL, fusionpbx_agent_uuid=NULL
2. Survey & Feedback Agent: sip_username=NULL, did_number=NULL, fusionpbx_agent_uuid=NULL
3. EPIC Sales Agent:        sip_username=3020, did_number=17678189025, fusionpbx_agent_uuid=NULL
```

### 2. API Key Format

The `fusionpbx_api_key` stored in database has format: `ak_d9b73cd80a8082ca8cb8e1bc125d8603`

This is **NOT a FusionPBX user UUID**, it's an API key generated by FusionPBX.

### 3. FusionPBX API Behavior

Testing the provision endpoint:
```bash
curl -X POST https://billing.call.epic.dm/api/ai-agents/provision \
  -H "Content-Type: application/json" \
  -d '{"user_email":"test@example.com","agent_name":"Test Agent"}'
```

Response:
```json
{
  "agent": {
    "agent_uuid": "668678af-b601-4df8-ae67-c5dd65aa64f0",
    "user_email": "test@example.com",
    "api_key": "ak_c9b64ad130a020c5e8421dcd25935956"
  },
  "sip_credentials": {
    "sip_username": "3022",
    "sip_password": "...",
    "did_number": "17678189027"
  }
}
```

**Key Finding**: The API returns `api_key` but NOT `user_uuid` or `fusionpbx_user_uuid`!

## The Problem

### Missing Data Flow

**Expected Flow**:
```
1. User creates agent via ai.epic.dm
2. FusionPBX API creates:
   - FusionPBX user account (if first agent)
   - SIP extension for agent
   - DID assignment
3. FusionPBX returns:
   - user_uuid (FusionPBX user UUID) ❌ NOT RETURNED
   - api_key (for billing consolidation) ✅ RETURNED
4. ai.epic.dm stores both in database
```

**Actual Flow**:
```
1. User creates agent via ai.epic.dm
2. FusionPBX API creates resources
3. FusionPBX returns ONLY api_key
4. ai.epic.dm stores api_key but NOT user_uuid
```

### Database Schema Issue

The `users` table has:
- ✅ `fusionpbx_api_key` (populated with ak_...)
- ❌ `fusionpbx_user_uuid` (NULL)

The `agent_configs` table has:
- ❌ `fusionpbx_agent_uuid` (NULL for most agents)
- ❌ `fusionpbx_extension_uuid` (NULL)

## Why User Can't Find Account in FusionPBX GUI

### Option 1: FusionPBX Creates User with API Key as Identifier

If FusionPBX creates users using the API key format, you would search in FusionPBX for:
- Username: `ak_d9b73cd80a8082ca8cb8e1bc125d8603`
- NOT email: `giraud.eric@gmail.com`

### Option 2: FusionPBX Creates User with Email but No Mapping

FusionPBX might create a user with email `giraud.eric@gmail.com`, but without the FusionPBX UUID stored in ai.epic.dm database, there's no way to correlate:
- ai.epic.dm user → FusionPBX user

### Option 3: FusionPBX Doesn't Create Individual Users

The FusionPBX API might be creating extensions and DIDs **without** creating individual user accounts. All agents might be under a single "system" account.
